# Screenshots: gallery sources and capture recipes

The README gallery embeds the committed e2e fixtures in
`tests/e2e/fixtures/screenshots/`. They are real captures of the running
app against synthetic demo data — no real user data — and are
regenerated by re-running the spec listed with each recipe below.

## Demo GIF (README front door)

The README front door embeds `demo.gif` (recorded 2026-11-18): a 16 s capture
at 960×600 (recorded from a 1280×800 window, light theme, synthetic fixture
data `tests/e2e/fixtures/archive.mbox`) showing the three scenes —
first-run "Add your first source" → Import file → preview → confirm,
then a search for "vault" with the top hit open in the reading pane and
matches highlighted. Captured headless: the v0.2.0 binary on `Xvfb` with
`xdotool` driving the real UI and `ffmpeg -f x11grab` recording; converted
with a two-pass palette (`palettegen`/`paletteuse`, 15 fps). A real
drag-and-drop onto the drop zone cannot be scripted with xdotool, so the GIF
uses the "Import file…" button and the native file chooser — the same flow a
keyboard-first user takes.

## Views not yet captured

The e2e runner needs `tauri-driver` and WebKitWebDriver plus a
cargo-built binary (`npm run test:e2e`); the frontend also boots only
inside Tauri (`src/main.ts` imports Tauri APIs at startup), so a plain
browser cannot render it. Until a capture lands, the README gallery
sticks to the four fixtures above. Each recipe below records the view,
the demo data, the theme, and the window size to use.

| View | Recipe (view / data / theme / window) | Exercised by |
| --- | --- | --- |
| Import preview and confirm | Import `tests/e2e/fixtures/*.mbox` via the import button; capture the preview step (bounded rows, counts) and the confirm state before anything is stored / sample archive on the first-run screen / light / 1280×800 | `tests/e2e/specs/02-import-mbox.e2e.mjs` |
| Ask answer with source links | Open the Ask tab, submit a question in local mode; capture the answer with its source-linked rows / demo seed / light / 1280×800 | `tests/e2e/specs/05-llm-ask-mock.e2e.mjs` |
| Settings — AI assistance | Settings → AI assistance: provider form (kind, host, key field) and the theme select / fresh vault, no key entered / light / 1280×800 | `tests/e2e/specs/09-settings-providers.e2e.mjs` |
| Theme triptych (light / dark / vesper) | Same view three times — the wide workspace with a search hit open — with the theme select set to light, dark, and vesper in turn / demo seed / one capture per theme / 1280×800 | theme select covered by `09-settings-providers.e2e.mjs`; capture manually via `npm run tauri dev` |

Manual capture (when a desktop is available): run `npm run tauri dev`,
on the first-run screen load the isolated sample archive (or import a
fixture `.mbox`), set the theme in Settings, size the window per the
recipe, and capture. Save the result under `docs/screenshots/` and add
it to the README gallery with descriptive alt text (view, layout state,
demo data, theme).
