## The gate rule

**No broader promotion without the readout, whatever else is green.** Green tests, a passing release matrix, signed binaries, a download page or any other engineering or launch evidence does not substitute for the readout and cannot select Proceed — that rule belongs to the [success plan's decision rules](../internal/user-success-plan.md#decision-rules) ("Passing tests alone cannot select Proceed") and to the staged gates behind the [U10 row](../internal/user-success-plan.md#prioritized-work-packages).

## What closes this gate

A dated gate readout, written **after observation** from a real cohort, containing at minimum the playbook's readout fields — recruited/qualified/completed/withdrew counts, the install → source ready → import → verified retrieval → activation funnel, task success and failure categories with raw denominators, support time total/median/range with repeating causes, contradicting evidence, and a decision (proceed / narrow / one focused iteration / stop) with owner, reason, next hypothesis and pass rule. The [pilot kit](u10-pilot-kit-2026-11-15.md) supplies the template and rubric. Raw participant counts are preserved; no invented or averaged-away evidence.

## Division of labor

- Repository-runnable (done here): the kit — screener, schedule, tracking log, readout template, this gate record.
- User-run only: recruiting the cohort, obtaining participant agreements, supporting participants for 30 days, and deciding. The truthfulness of a future readout cannot be verified by agent-run checks; the gate owner owns it.
- This repository holds aggregate findings and synthetic evidence only, never private archives or participant-identifying data ([docs index](../README.md)).
