### M2 completion record (2026-11-05, M2 code complete at `57f40c8`, spec tree at `1115eac`)

**Revisions.** M2.1 database pool + background job engine — writer worker, two read connections, per-connection initialization, bounded write/job queues, typed job states/errors, event log with monotonic sequence and polling recovery, v2 `job_*` commands and `job-event` window events — #40 (`00ed975`). M2.2 bounded streaming ingest — parser interfaces yielding one item at a time, batched commits with issue records, cooperative cancellation, checkpoint restart recovery, bounded media pass — #42 (`fbdf964`). M2.3 IMAP coordinator — rounds over every configured non-excluded source, fetch outside storage ownership, atomic occurrence/checkpoint/ledger commits, durable failed-item accounting, UIDVALIDITY epoch resets, per-source exclusion — #41 (`0dc393e`). M2.4 opt-in job-backed scheduler plus the real-path performance harness (paginated search, IPC-shaped round trips, concurrent ingest, pool startup) — #43 (`84895d9`), with the interval-preservation/status-normalization fix #50 (`57f40c8`).

**Changed behaviors.** The archive is no longer served through one guarded connection: every command and job reads and writes through the pool (writer thread + two read connections + job runner), and network/parsing waits happen on job threads with no connection held — a stalled IMAP fetch blocks neither searches nor writes (proven at single-account and coordinator-round scale). All production imports run the bounded streaming path (at most 200 items or 8 MiB of body text per atomic batch commit, issue records and checkpoint advance in the same transaction, media extraction on the driver thread before commit); the whole-archive `collect` helpers remain only for small parser tests. Cancellation is cooperative per item and discards only the uncommitted partial batch: committed data and reported counts always agree, and a cancelled or interrupted import resumes from its committed position without duplicates or lost failures (import identity is path + length + mtime, so an edited file is a new import, never a shifted resume). IMAP sync commits message rows, occurrences, failed-item ledger rows, and the checkpoint in one transaction per fetch batch (≤50 messages); items that cannot be stored are ledgered with fixed reasons and retried every round until they resolve, and a UIDVALIDITY reset rescans and dedups while clearing the abandoned epoch's ledger rows. Coordinator rounds skip excluded sources, report sources without credentials instead of erroring, and never let one failing source sink the round. The periodic scheduler is opt-in (off by default, 15-minute default interval clamped to 1 minute–24 hours), persisted in the vault, submits rounds as ordinary `imap_sync_all` jobs, never overlaps rounds, and collapses sleep/resume/offline gaps into exactly one catch-up round. The performance harness now times the real paginated query path (FTS5 MATCH + filters + LIMIT/OFFSET + COUNT + snippets) with per-query p95 CI budgets, and the historical `search_filtered` tables are preserved verbatim below the current results.

pool sync matches direct sync archive-for-archive; events serialize flat for the frontend. `--test bounded_ingest` 21 passed, 1 ignored — stream/collect parity per format with skip determinism, both batch limits honored, issue records durable with positions and idempotent across reruns, cancellation preserves committed data and counts, cancelled runs resume and complete without duplicates, restart recovers from the last committed position, the bounded import runs through the pool, and the driver never holds more than one batch; the ignored heavy test `large_generated_input_stays_within_memory_budget` was run separately with `-- --ignored`: **passed** — 153.6 MB Telegram JSON + 137.7 MB WhatsApp text (150k messages each) imported with peak RSS growing 9.1 MB against the suite's 96 MB budget. `--test imap_coordinator` 10 passed — a round syncs every configured source and exclusion skips one, no-credentials is reported (a failing resolver is Failed, not NoCredentials), interruption mid-fetch leaves checkpoint and archive in agreement, a mid-batch storage fault rolls back the whole batch, checkpoint recovery works across a pool restart, a missing fetch is ledgered and heals next round, an unreachable source fails alone, and searches and writes complete while a round is parked on the network. `--test scheduler` 12 passed — schedule defaults off at 15 minutes, persists and survives reopen, clamps to configured bounds, a persisted out-of-bounds interval arms normalized (#50), rounds fire per interval as plain jobs, a round outlasting the interval neither overlaps nor queues, a clock-jump gap collapses to one catch-up round, disabling cancels the active round, failed rounds keep the cadence, and status publishes transitions. `--test imap_sync` 14 passed — the batch machinery under the coordinator against the mock IMAP server: durable instances, multi-folder occurrences, conflicting revisions flagged, atomic fetch-batch commits with mid-batch fault rollback, failed-item ledger accounting including retry/resolution and UIDVALIDITY-reset clearing, durable across reopen.

**Acceptance mapping.** A05 (slow network while searching, cancel and restart at batch boundaries): the network-stall proofs in `jobs` and `imap_coordinator` plus the cancellation/resume/restart tests in `bounded_ingest`; readers never waited behind a write in the concurrent-ingest measurements ([BASELINE.md](../tests/perf/BASELINE.md)); concurrent imports are bounded by the single runner thread (imports serialize, reads continue). A06 (missing UID/body, parse failure, transport disconnect, per-folder error, cursor commit failure): the `imap_sync` ledger/rollback suites and `imap_coordinator`'s missing-fetch, interruption, and mid-batch-fault regressions, plus durable `import_issues` in `bounded_ingest`. A11 (large datasets, query while ingesting, deep pages, broad common terms, bounded memory): [BASELINE.md](../tests/perf/BASELINE.md) M2.4 records — p50/p95/p99 for ten query shapes at 100k and 1M (including deep FTS/browse pages, rare-selectivity terms, and the ubiquitous worst case), IPC-shaped round trips with serialization, search-while-ingesting at 100k/1M, startup including `DbPool::spawn`, and the heavy memory-budget proof above; a literal zero-hit query was not separately profiled (no-match behavior is covered by the correctness suites, and an empty FTS result is the cheapest shape by construction).

**Migration/recovery evidence.** Migrations 9–11 are additive (failed-item ledger + exclusion flag; `import_checkpoints`/`import_issues`; the `sync_schedule` singleton) and apply through the M1.4 safe-migration path (snapshot, preflight, single-transaction conversion, validation, rollback) — no existing vault data is rewritten. Interruption injections at every batch boundary: a dead connection mid-fetch leaves the cursor at the boundary of durably stored work; an injected mid-batch storage fault rolls back the entire batch with the cursor unmoved; a pool restart mid-import resumes from the committed checkpoint without duplicates; cancellation mid-import preserves committed rows and counts and the resumed run completes cleanly; completed reruns neither duplicate messages nor issue records.

**Failures/limitations.** Job records live in the process registry, not a database table: no `interrupted`/`partial` states, no linked retry jobs, no per-item outcome counters in events — job history does not survive an app restart (the jobs panel starts empty), and resumability is carried by the durable checkpoints/ledgers instead. All background jobs serialize on one runner thread (stricter than the proposed "at most two ingest jobs"; the only per-source admission control is the IMAP exclusion flag). The connection busy timeout is 5 seconds, not the 2 seconds sketched in the proposal. Cancellation is cooperative and bounded by the current item, batch, or socket call; no cancellation-latency measurement was recorded, so the 200 ms acknowledgment target remains unmeasured. The scheduler drives IMAP rounds only (watched folders and embeddings have no schedule). Performance was measured on the paginated `search_page` path plus serialization — the v2 command surface (`search_archive_v2`) and the webview/OS hop are not separately measured, the stalled-network search target (≤ 2× idle p95 + 100 ms) was proven qualitatively (non-blocking) rather than timed, and 1M results are informational. Frontend and E2E suites were not rerun for this documentation change.

**Remaining work.** Deferred: a persisted job-record ledger with `interrupted`/`partial` states and linked retries (revisit when a jobs panel needs cross-restart history — a product call, not a correctness gap); keyset pagination for deep pages (recorded as an observation in BASELINE.md); v2-path and end-to-end display timing and the proposed targets table's desktop measurements (F10 remainder); scheduled non-IMAP job kinds if the product wants them.

**Changed behaviors.** Results are a flat stable list: relevance sorts by FTS5 rank then ascending message id, newest by resolved instant descending then id descending with unknown instants deterministically last; empty text browses newest regardless of the requested sort. The count and rows of one page are read in a single deferred read transaction and carry that snapshot's `archive_revision`, so a commit between pages surfaces as a visible "results have new data" notice with Refresh — rows never move or change under the cursor, and pagination is never silently restarted. Snippets are bounded (500 Unicode characters including hit markers for text search; a 240-character body prefix for browse). Day bounds interpret in a validated IANA timezone (empty = OS default), covering whole local days including 23/25-hour DST days; reversed bounds are rejected in the UI before invocation and again in storage; unresolved/missing instants are excluded from bounded searches, sort last in browse, and render as "No date" rather than a fabricated timestamp. Reading pages chronological context by message-id cursors without losing the anchor; an unverified legacy grouping returns the anchor alone flagged `unverified_conversation` ("Conversation could not be verified"), never guessed neighbors. Message detail carries body, time provenance, attachments with honest availability (preserved media vs explicit missing references), occurrences with import provenance, and conflicting-revision links. A pasted `mailchat://message/<id>` locator opens that message directly; Copy link places the same locator on the clipboard, and Copy message includes readable text plus provenance (source, conversation confidence, date and confidence, original timestamp, attachment availability, revisions, occurrences). Selection export writes UTF-8 text or JSON with provenance for the explicitly checked rows in their order (bounded to 10,000 ids per file, attachments never implicitly included) to a native-picked destination. Stale-response protection moved from four per-panel inline counters into `SequenceGuard`/`Sequence`; returning from reading restores the selected row and scroll. The shell moves imports, account configuration, and maintenance out of the reading surface into navigation destinations (All messages / Add source / Activity / Settings) with per-source scope chips; a job started before navigating away keeps running and reports through the Activity panel.
