## Workspace and navigation

The archive workspace has three areas: source navigation, results, and reading. Search remains local and is the primary action. Imports, account configuration, and maintenance live outside the reading surface.

```text
Desktop, width >= 1100px
┌──────────────────┬────────────────────────────┬─────────────────────────────┐
│ Mailchat Vault   │ Search messages…      [Go] │ Ana · Delivery date         │
│ Archive          │ [Person] [Dates] [Files]    │ Date · source · conversation │
│ Sources          │ [Active filters] [Clear]   │ Original message            │
│ Settings         │ 1–50 of 1,234   Relevance  │                             │
│ [source chips]   │ Author / subject / date    │ [Available attachment]      │
│ Activity       2 │ Match snippet…             │ Conversation context        │
│                  │ Next result…               │ [Load earlier] [Load later] │
│                  │                            │ Provenance ▸                │
│                  │ [Previous]       [Next]    │                             │
└──────────────────┴────────────────────────────┴─────────────────────────────┘
```

At 1100px and above use a 208px navigation column, a results area of at least 320px, and a reading area of at least 400px. Allocate remaining width to the reading area; give each area independent vertical scrolling. The initial window is 1280×800 where available, with 640×480 minimum; respect smaller available screens.

From 800px to 1099px show navigation and results; opening a message replaces the results area with a reading view and a visible “Back to results” action. Below 800px show one content area and a labeled navigation toggle. Preserve query, filters, page, selection, and scroll when returning. All controls remain reachable at 200% zoom; a viewport narrower than the nominal minimum uses the compact layout rather than horizontal clipping.

**Current (M3.1; updated for the Phase-1 navigation restructure).** The three-area shell, the 1100px/800px breakpoints with independent per-area scrolling, the 1280×800 default window with a 640×480 minimum, the medium-layout Back-to-results swap, and the compact drawer (labeled toggle, `aria-expanded`, Escape close, removed from the accessibility tree when closed) are implemented in [workspace.ts](../src/workspace.ts)/[state.ts](../src/state.ts), with semantic design tokens ([tokens.css](../src/styles/tokens.css); light/dark/System via the theme setting) and the bundled Source Sans 3 (SIL OFL 1.1 license committed at [src/assets/fonts](../src/assets/fonts)); 1280px at 200% zoom resolves to the compact layout with no horizontal clipping. Navigation destinations are **Archive**, **Sources**, and **Settings**, with **Activity** as a secondary link at the bottom of the navigation column — its badge counts active background jobs and a failure raises a textual "needs attention" flag until Activity is opened; there is no separate Accounts destination (the accounts overview merged into Sources). The Sources view is one screen with sub-sections: the **home list** shows every source (email and imports) with its name, kind, message count, last import/sync, and sync state, primary actions **View messages** (scopes the archive to the source's stable instance id, keeping the typed query) and **Sync now** (email), and a **Details** fold holding Pause/Resume, Update credentials…, Forget credentials, and the two-step Disconnect…; **Add source…** opens a chooser offering exactly Import files… and Connect email… (the email form has visible field labels with server/port/folders behind an Advanced fold); **Automatic imports…** holds the shared auto-sync toggle and folder watching. Sub-section transitions transfer keyboard focus to the incoming section's first control. Settings is split into **General**, **Storage & backup**, and **AI assistance** pages, each with its own Save that posts the full form; storage data (the M4.4 backup/restore/previous-vault group and the Media store report) loads only when the Storage & backup page opens. Source chips in the navigation column select by stable instance id: two sources sharing a display label stay independently selectable with disambiguated chip labels, and only labels present in the stats counts get a chip. Not-yet-implemented items this section still tracks: the per-entry DST pickers and the day/month date-order choice (M3.3). The items previously listed here have since shipped: per-source status text on the chips (2026-11-16) — each chip carries its source's short status beside the label and count ("Syncing…" while a manual sync or a scheduler/tray `imap_sync_all` round runs, "Needs sign-in" when no credentials are stored or the last failure was about them, "Sync failed — <reason>" for other recorded failures, "Paused" for excluded accounts, "Last synced <time>"/"Never synced" for connected email, "Imported <time>" for file imports; the label-and-count text and selection by stable instance id are unchanged) — and the running-import progress surface inside the import flow plus the timezone confirmation card, which landed with the first-session slice (2026-11-15, GP03: the inline progress card with an in-place Retry).

### Navigation rules

- Archive browses newest first, including on first launch with an existing archive. An empty vault shows setup guidance instead.
- Selecting a source scopes the current search and resets pagination. It does not erase typed search text. Archive clears source scope while retaining other filters.
- Source labels are user-facing names, not provider namespace strings. A status indicator has text such as “Syncing”, “Needs sign-in”, or “Last synced today at 09:20”. File imports show “Last imported”.
- Add source opens a dedicated setup view with “Import files” and “Connect email”. Activity lists jobs; Settings contains General, AI assistance, and Storage & backup; source management lives in the Sources view.
- Closing setup returns to the previous workspace. Once a job starts it continues when navigating away; its progress remains in Activity.

### Search and selection

Submit on Enter or Search. Filter changes submit immediately; reset to page one. Do not add remote suggestions or automatic search on every keystroke in this release. Empty text means browse. Text defaults to Relevance; empty text defaults to Newest. Users may choose Newest for text searches; preserve that choice until cleared.

Show applied source, person, date, and “Has attachment” filters as removable chips. An attachment filter matches both available and explicitly missing references; show file availability on the result. Date bounds use the workspace timezone and include the entire selected days. Reject reversed ranges inline before invocation; unknown dates are excluded when bounded and explained in the filter help.

Results are a flat ordered list; do not regroup them by conversation. Each row shows sender, subject or conversation label, date, source, two-line snippet, and attachment availability when relevant. Use backend hit markers for highlighting. Show “No date” or a time-uncertainty indicator instead of a fabricated timestamp.

Keep 50 results per page, exact count, and Previous/Next. Preserve existing stale-response protection. After archive changes, mark results as having new data and offer Refresh; do not move rows or change selected content under the user's cursor. A fresh submission resets selection and page; returning from reading restores both.

Reading shows the full plain-text message first, then attachments and bounded chronological context. Email exposes From, To, Cc, subject, and reply relationships. Chat exposes participants, replies, and conversation name. Load earlier/later context in pages without losing the anchor. An unresolved legacy grouping shows “Conversation could not be verified” and the selected message alone, not guessed neighbors.

**Current (M3.2).** Search/selection runs on the v2 reading surface (`search_archive_v2` / `message_detail_v2` / `conversation_context_v2` / `list_import_scopes_v2` / `export_messages_v2`): flat results with stable ranking, removable filter chips (source, author, dates, "has attachment", import scope) plus a sort choice, 50-per-page exact counts with Previous/Next, stale-response protection centralized in `SequenceGuard`/`Sequence`, the archive-revision "new data" notice with Refresh, backend hit-marker highlighting, "No date" for unknown instants, context pages by message-id cursor without losing the anchor, the honest unverified-grouping reading pane, copy message with provenance / copy `mailchat://message/<id>` link, pasted-locator deep links, and restorable selection and scroll on Back. Snippets are bounded to 500 Unicode characters including hit markers (a 240-character body prefix when browsing). Reversed day bounds are rejected inline before invocation. Selection export writes UTF-8 text or JSON with provenance for the checked rows in their order (bounded to 10,000 messages per file) to a native-picked destination; the reading pane shows provenance behind its expandable disclosure with raw JSON behind the "Technical details" fold. Not yet implemented: persisting the workspace timezone (each request defaults to the OS zone).

Copy message includes readable text and provenance; Copy link uses an internal `mailchat://message/<id>` locator handled within the app. It is a vault-local reference, not a public URL and not a cross-vault identifier. Export selection offers UTF-8 text or JSON with provenance; attached files require a separate explicit export selection. Metadata disclosure includes original timestamp, source occurrence, import job, and legacy uncertainty; raw JSON stays behind “Technical details”.

## Import and first success

**Mixed** — the first-source journey landed with the import surface (the M3.3 first slice): an empty vault presents the first-run card below (“Add your first source” + “Try a sample archive”); the sample archive is a private in-memory vault (reads route there while it is open, every personal-vault write refuses, leaving restores the personal vault without ever having touched it — `demo_enter`/`demo_leave`/`demo_status`); import starts from one native picker (file or folder: mbox, chat TXT/JSON, ZIP) with no typed path; the `preview_import` command renders a bounded preview card (detected format, sample messages, counts as lower bounds when the scan caps, parse-failure count, detected/missing media, input bytes, free-space estimate that disables Import when the archive likely does not fit, per-format export hints, friendly errors instead of raw errno); a finished import offers “View imported messages” scoped to exactly that run; and empty text browses newest-first from boot (the workspace shows the archive without a first manual search). GP03 (2026-11-15) landed the remainder's core: the preview's confirmation card (naive-stamp count, assumed zone preselected from the OS, confirmed or corrected once per run; DST folds keep the first occurrence and gaps stay unresolved, both stated), the explicit destination-source chooser (the derived name preselected), the inline progress card with an in-place Retry for failed imports, completion recovery actions (parse failures open Activity, missing media name the re-export-with-media path), and supported-format help on the first-run card and the add-source chooser. Still open: per-entry DST pickers and day/month date-order choice, conversation-level user linking of legacy groupings, naive mail Date headers (still UTC-assumed), and the five observed first-source sessions ([kit](evidence/first-session-kit-2026-11-15.md)).

1. Empty vault presents “Add your first source”, a short local-storage explanation, and a secondary “Try a sample archive”. Sample data uses an isolated temporary vault; leaving it restores the personal vault without mixing demo rows into real data. **Current** (the isolated vault is in-memory in the app process, not a temporary file).
2. Choose Import files. Native selection accepts mbox, chat TXT/JSON, a directory, or ZIP. Show source-specific export instructions locally; unsupported formats receive an actionable explanation. **Current** (one file picker + one folder picker; unsupported picks get the actionable message in the preview status).
3. Preview shows detected format, chosen source collection, conversation identity if known, sample messages, timestamp interpretation, detected/missing media, total input bytes, and free-space estimate. Preview is bounded; do not claim exact message counts without a complete scan. **Current except** conversation identity, timestamp interpretation, and the date questions (proposed, with the remainder above).
4. Existing source selection is explicit. Telegram stable chat IDs may identify the conversation within that source. WhatsApp prompts “New conversation” or “Add to an existing conversation”; display the last import and a small sample before linking.
5. Ambiguous date order requires day-first/month-first selection. Naive timestamps require a timezone, preselected from the OS and explicitly confirmed. DST overlaps require choosing the earlier/later interpretation for affected entries; gaps remain unresolved with their original text unless corrected. Permit import with an explicit unresolved status.
6. Explain that supplied files will be copied and that absent media cannot be recovered. Show available space and configurable capacity limits before starting; lack of required space disables Start with guidance.
7. Start returns a job immediately. Display stage, messages processed, new/existing/failed counts, media bytes copied, and Cancel. Use indeterminate progress when the total is unknown.
8. Completion offers “View imported messages” with an import-job filter (**current**; the partial-success review/retry affordances remain proposed). Show skipped system/service entries separately from parse failures (proposed).

Cancel file selection makes no changes. Cancelling preview discards temporary files. Cancelling a running import preserves committed records and files; the summary states that partial data remains. Retry targets the failed/unfinished work, not a duplicate source.

## Connected email

**Proposed (M3.4)** — today the app-password/Google-sign-in IMAP controls live in the Add source view (sources panel), and per-account sync/pause/forget-credentials management lives in the multi-account Accounts panel (inventoried in the root [README](../README.md)); there is still no account page with folder selection, credential-update flow, or disconnect/local-deletion separation.

Choose Gmail preset or Custom IMAP. Keep host, port, and TLS details under Advanced for Gmail. Use visible labels for email/username and password; explain app-password requirements without promising OAuth. Validate host, port, and required values before testing the connection.

Connection testing runs in the background and does not save an invalid replacement password over a working one. After success, select folders (INBOX default), name the account, and choose manual sync or opt-in 15-minute sync. The credential store notice reads “Saved in your system keychain” or “Kept for this session only”. Do not present memory fallback as persistent storage.

An account page shows folders, last attempt/success, message/media counts, failures, Sync now, Cancel, credentials, and Disconnect. Authentication failure offers Update credentials; network failure offers Retry. A folder failure does not conceal success in other folders. Disconnect confirmation explains that scheduled access stops and credentials are removed while archived content remains.

Deleting local archived content is a separate action with source name and counts. It never deletes remote mail. Require confirmation, exclude concurrent jobs for that source, and remove shared object bytes only when unreferenced.

## Media and storage

Attachment rows show filename, type, size, and availability. Available images have bounded thumbnails and an accessible full preview; audio/video have user-initiated controls with no autoplay. Unsupported formats offer Export or Open externally after an explicit user action. PDF and office files use external opening in this release. Executable files have Export only. Never render HTML mail or active attachments as application HTML.

Missing references say “File was not included in this export”. Failed copies say “Could not preserve this file” with Retry and the job issue. Unmatched export files appear under the source's Files tab as “Not linked to a message”; do not assign them by proximity or filename guessing.

Storage & backup shows database, originals, media, staging, and free-space sizes. Backup opens a destination dialog, explains that the backup is not app-encrypted and excludes credentials, then reports progress. Restore first shows backup metadata, integrity results, required disk space, and a warning that switching archives replaces the active view. The old vault remains recoverable. Settings offers “Return to previous vault” after a successful switch. Do not automatically delete recovery copies.

**Current (U05 remainder).** The Storage & backup group leads the Settings view (F10's targeted half — the safety/location questions before provider configuration; no full reorganization). It states the archive's location (the vault data dir), the persisted “Last verified backup” line (when, where, how big, the captured counts — read from the vault's own metadata so it survives restarts, with an honest “the file is no longer at that path” when the recorded container was moved or deleted), and, after any restore or return, the restart origin line: what vault is active, since when, from where — including what startup recovery did to an interrupted switch (“rolled back at startup — the vault from before it is active”). A folder's sync status line also renders its media-pass counters (stored/deduped/missing, only the non-zero parts).

**Current (M4.3, #58).** Preserved media objects (the M4.1 store's chat-export media referenced from `raw_json` — lifecycle owned by [Architecture](architecture.md#originals-media-and-object-lifecycle)) render in the reading pane: images inline, audio/video with user-started playback only (no `autoplay`, minimal preload; `.tgs`/`.webm` stickers stay rows), and everything else — documents, HTML, unknown kinds — as a row with explicit actions only; HTML in an attachment is data to export, never content to execute. Every preserved object carries explicit *Save a copy…* (byte-exact export to a native-picked path) and *Open externally…* actions; external open copies into a disposable per-digest temp preview (private 0700/0600, prior copies purged so only the most recent open's copy survives) so no external writer ever touches the content-addressed store. Preserved objects are served read-only by the app's `mcmedia://` protocol — strict single-component `<sha256>.<ext>` name validation, byte ranges, hard response CSP with HTML never a servable type — so the frontend never receives an unrestricted filesystem URL, nothing autoplays, and nothing is fetched remotely to display media. The Settings Media store section shows the usage report: object count and total bytes, the referenced/orphaned split, a per-extension breakdown with bars, and the largest objects. Not yet implemented: the per-reference explicit availability UX above (“File was not included in this export” / “Could not preserve this file” with Retry) and the *Files* tab of unlinked source files — the underlying M4.2 missing-state and unlinked-registry data landed with #60 ahead of its acceptance record, so these remain UX-polish and record-pending rather than unstarted — and the Storage & backup size breakdowns (database/originals/staging sizes; the group itself, its dialogs, and the U05 persisted/origin lines landed with M4.4/#67 and the U05 remainder).

## Optional Ask

Ask is a secondary mode beside Search in the results area, not a competing full-width section. Ordinary search remains available throughout.

AI settings default off even if provider keys are present. Show endpoint host, model, and credential availability; store newly entered keys in the OS keychain or session memory. Preserve compatible environment configuration as an available configuration source, but it never overrides the consent switch. *Superseded in its switch half by decision (2026-11-16, [#181](https://github.com/acailic/mailchat-vault/issues/181)): there is no persisted consent switch — consent is session-scoped (in-memory only, reset on every app start), which is how "default off" ships; the visibility, key-storage, and environment-configuration sentences are current.*

For each question, show that the question and date/timezone context will go to the selected endpoint. “Find matching messages” is the explicit send action. Run translation, validate the plan, intersect with active source/person/date/file filters, and show local results. Explain fallback in plain language; keep FTS details expandable.

Before synthesis, show a preview of the exact numbered context: at most eight results, body text capped at 500 Unicode characters each, bounded author metadata and timestamps, no attachments or raw JSON. “Generate answer” approves that payload and the question for that endpoint. Changing the endpoint, question, filters, or result snapshot invalidates approval. Declining leaves local results usable. No persistent blanket approval is offered in this release.

Answers label their evidence scope (“Based on 6 matching messages”). Citation buttons open the referenced original in the same reading pane. Unknown citation numbers are not clickable and cause a visible unsupported-citation note. Failure leaves results available and offers retry. Never label a generated answer as proof of archive completeness.

**Current (M5, consent and source-linked answers).** The backend-enforced consent gate and the source-linked answers are implemented (#48, recorded in the [M5 progress record](implementation-roadmap.md#completion-tracking)): nothing is sent to any provider without an explicit, per-session consent — the first network ask of a session runs fully locally and shows a per-question prompt stating exactly what would leave (the question, then the top `summarize_top` — currently 8 — matching messages with bodies truncated to 500 characters, to the named model via host) with *Send & ask for this session* / *Keep asking locally*; agreeing re-asks the same question with the network leg enabled. Consent is session-scoped (in-memory only, resets on every app start, never persisted — no persistent blanket approval), always visible in a status line, and revocable mid-session; the prompt re-renders when the provider selection changes so it always names the destination a consent click would actually use. Endpoint host, model, and key availability are visible in Settings and the provider menu, with keys in the OS keychain or session memory and environment configuration available as a fallback (editable in Settings) that never overrides consent. Answers render their citations `[1]`, `[2]`, … as clickable links, and the numbered source rows beneath the answer match those numbers; either opens the original archived message in its conversation context in the v2 reading pane. Every answer carries a “Based on N matching messages” evidence-scope caption stating how many matching messages the summary was built from (N is the result count capped by the summary window), and citations beyond the summarized window or outside the result list stay plain text, never dead links, with a visible unsupported-citation note naming the unlinkable markers; failure leaves the local results usable (translation failure falls back to a plain term plan, summary failure shows an explanatory note). Not yet implemented: the per-question send disclosure of the second paragraph as a separate step (the consented ask translates and summarizes in one flow), the exact numbered-context preview and digest-bound *Generate answer* approval of the third paragraph, the Ask-surface half of filter intersection with the active workspace filters (the backend accepts and enforces an optional validated scope on the ask — validated before retrieval, intersected with the generated plan so it can only narrow, applied identically to the lexical and vector legs, and never escaped by an unscoped fallback — but the frontend does not yet send the filter snapshot, show the scope line with its explicit “Entire archive” state, or invalidate pending results when the scope changes), and in-flight cancellation — all proposed for the M5.2 remainder. The persisted off-by-default switch of the first paragraph is not pending: it is superseded by the 2026-11-16 product decision ([#181](https://github.com/acailic/mailchat-vault/issues/181)) — session-scoped consent (in-memory only, reset on every app start, never persisted) is the decided release behavior, not an interim state.

## Accessibility and interaction

- Use real buttons, labels, landmarks, headings, and native fields. Do not implement mouse-only list items. Keep results as a semantic list with focusable message actions.
- Cmd/Ctrl+K opens the command palette: a combobox over every registered command plus recent searches (persisted per machine), fuzzy-matched with visible highlight, grouped Actions / Views / Recent searches; arrow keys move the active option with `aria-activedescendant`, Enter runs, Escape closes and returns focus to the trigger, Tab is trapped while open, and keyboard opens render instantly (no entrance animation; only a pointer open may fade, opacity-only, removed under reduced motion). `/` focuses search; ignore `/` while typing in editable fields. Arrow keys move result selection only when results own focus; Enter opens; Escape returns/closes without erasing the query. Tab always reaches controls. Native audio/video and text inputs retain native key behavior.
- In compact reading views, focus the message heading on open and restore the initiating result on Back. In wide layouts preserve keyboard focus on the selected result unless the user enters the reading pane.
- Setup/confirmation dialogs trap focus, have a labeled purpose, close with Escape when safe, and restore the trigger. Progress never steals focus.
- Announce completed searches, job transitions, and errors using appropriate live regions; throttle progress announcements. Visible text accompanies icons and colors.
- Target WCAG 2.2 AA contrast and interaction behavior. Verify with the checks in [Validation](validation-and-release.md#ux-and-accessibility), rather than claiming conformance from CSS alone.

## Visual direction

Use a quiet reference-library aesthetic with dense but comfortable message rows. Bundle Source Sans 3 with its license, falling back to native UI fonts. Body text is 15px/1.5, metadata 13px, section titles 18px, and page titles 24px. Use a 4px spacing scale, 8–12px row padding, restrained 4–6px radii, and borders rather than decorative card shadows.

Define semantic tokens for canvas, panel, text, muted text, border, accent, selection, match, success, warning, and danger. Start with warm neutral light surfaces and a forest-green accent; provide a dark equivalent and System/Light/Dark settings. Final token values must pass measured contrast. Use an amber search-match highlight distinct from selection. Keep message lines near 70–85 characters where space permits.

Motion uses the shared token vocabulary (`--motion-fast` 120ms, `--motion-standard` 180ms, `--motion-slow` 240ms for dialogs/large surfaces only, with `--ease-out`/`--ease-press`) for opacity/transform state transitions; the `prefers-reduced-motion` block removes all movement and ambient animation while keeping opacity/color feedback. Do not animate message reorderings, use autoplay media, fetch fonts remotely, or decorate the workspace with metrics unrelated to retrieval.

## State and recovery matrix

| State | Presentation | Available recovery |
| --- | --- | --- |
| Empty vault | First-source guidance | Import, connect, sample |
| No matches | Query and active filters; no blame | Edit terms, clear filters, browse source |
| Loading search | Existing rows visibly marked as previous results; busy status | Submit replacement search |
| Search failure | Last successful results labeled as previous | Retry; edit filters |
| Missing selected message | “Message is no longer in this vault” | Back to results and refresh |
| Partial import/sync | Counts plus item/folder issue list | Retry issues; open successful data |
| Cancelled job | Committed progress and remaining work | Resume/retry |
| Low disk space | Stage and required/available bytes | Choose capacity/destination; retry after freeing space |
| Keychain unavailable | Session-only notice | Continue for session or retry storage |
| Notification permission denied or OS notifier missing | No notification — the synced/imported data is already stored and visible in Activity | Re-enable the Settings toggle to re-request permission |
| Unsupported preview | Preserved file metadata | Export or explicitly open externally |
| Restore validation failure | Specific damaged/missing components | Keep current vault; select another backup |
| Restart after restore/return | Origin line in Storage & backup: what vault is active, since when, from where (and what startup recovery did to an interrupted switch) | Return to a previous-vault snapshot; create a fresh backup |
| No verified backup | Honest empty state explaining the line | Create backup… |
